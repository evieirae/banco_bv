###Prompt para Análise Técnica e Elegibilidade de Migração SAS
Contexto: Estou atuando como Engenheiro de Dados em um Projeto Piloto de migração de um legado SAS para uma stack moderna (dbt + BigQuery). Tenho o conteúdo de um arquivo de código SAS e preciso de uma análise técnica para decidir a estratégia e a viabilidade imediata da migração.

Sua Função: Atue como um Engenheiro de Dados Sênior e Tech Lead focado em Governança.

Instrução Principal: Analise o código SAS fornecido ao final deste prompt e gere um relatório técnico. A saída deve ser estritamente formatada em Markdown (.md) para cópia imediata.

###Estrutura Obrigatória do Relatório
Relatório de Análise Técnica: [Nome do Arquivo/Processo]

1. Resumo do EGP (Fluxo Lógico)
* Objetivo: Explique em alto nível o propósito de negócio do código (ex: cálculo de comissões, geração de base de inadimplência).
* Principais Etapas: Descreva sucintamente o fluxo de dados (ex: "Conecta no BigQuery, filtra tabela X, faz join com Y, aplica PROC SQL e exporta").

2. Identificação de Entradas e Saídas
Entradas (Inputs):
* Liste as tabelas de origem.
* Identifique a Tecnologia da Origem: (Ex: Tabela BigQuery, Tabela SAS de Rede, Arquivo Excel, Oracle, DB2).

Saídas (Outputs):
* Liste as tabelas geradas.
* Classificação: Classifique como Temporária (WORK) ou Permanente (LIBNAME/Arquivo Físico).

3. Análise de Conversão e Recomendação
* Diagnóstico Técnico: Avalie a complexidade da tradução para SQL/dbt. O código é compatível? Requer lógica complexa de Data Step?
* Ação Recomendada (Mensagem para Negócios): Escreva uma pergunta colaborativa para a área de negócios para validar o consumo do dado (ex: "Hoje esse Excel é usado para quê? Podemos substituir por um Dashboard?").

4. Parecer de Elegibilidade (Fase Piloto)
Esta é a seção crítica para decisão. Avalie se o código cumpre os pré-requisitos para entrar na esteira de migração agora.

Critérios de Bloqueio (Checklist):
[ ] Utiliza Machine Learning ou Estatística Avançada? (Ex: PROC REG, ARIMA).
[ ] Utiliza Comandos de SO/Shell Script? (Ex: X, SYSTASK, PIPE para mover/descompactar arquivos).
[ ] Não gera saídas (Processo "fantasma" ou incompleto)?
[ ] Dependência de Legado (Consome tabelas SAS em rede, Excel ou bancos não migrados)?

Veredito Final: Escolha uma opção: 🔴 [DESPRIORIZADO] ou 🟢 [ELEGÍVEL].

Justificativa (Texto para E-mail): Escreva um resumo executivo dos motivos.
* Se Despriorizado: Liste os fatores principais (ex: Dependência de Legado, Infraestrutura Manual, Complexidade de Saída).
* Se Elegível: Confirme que as fontes são nativas e o código é determinístico.

5. Próximos Passos e Requisitos para Elegibilidade
Instrução: Se o projeto for DESPRIORIZADO, preencha esta seção com as ações corretivas necessárias. Se for Elegível, marque como "Iniciar Migração".

Liste o que precisa ser feito para desbloquear o projeto, mapeando o problema técnico para a solução de engenharia:
* Ingestão de Dados: (Use este item se houver Dependência de Libnames). Liste quais origens precisam ser migradas para o BigQuery.
* Automação de Ingestão: (Use este item se houver Shell Script/Comandos de SO). Explique que a manipulação manual de arquivos deve ser substituída por pipeline.
* Mensagem Padrão: (Adicione sempre este texto ao final): "Importante: O projeto permanecerá em nosso backlog e será automaticamente repriorizado assim que essas dependências de dados forem concluídas. Em breve, enviaremos comunicados oficiais detalhando o plano de ação para a resolução e ingestão dessas bases legadas."

6. Evidências Técnicas (Detalhamento dos Bloqueios)
Instrução: Preencha esta seção obrigatoriamente se o veredito for DESPRIORIZADO. Se for Elegível, marque como "N/A". O objetivo é provar tecnicamente o motivo do bloqueio.

Liste os trechos de código ou caminhos que inviabilizam a migração imediata:
A. Comandos de Sistema Operacional (Shell Script):
* Evidência: Liste o comando exato encontrado (ex: filename pipe 'ls...', call system...).

B. Dependência de Libnames de Rede (Legado):
* Libname: Nome da libname.
